# 开箱必读 · 档案交接实验室

第一届“红码杯”安全代码类示例作品。体验者扮演一场当代教学展的档案保管员，为三种用途制作交接副本，学习最小必要披露和文件完整性核验。

## 打开作品

1. 如果拿到 ZIP 压缩包，先完整解压。
2. 双击同目录的 `index.html`，使用新版 Microsoft Edge 或 Google Chrome 打开。
3. 点击“打开第一份委托”。本机即可完成全部练习，只有主动点开史料原文时才需要联网。

无需安装依赖、启动服务或登录。目录中的 assets 文件夹要跟 index.html 放在一起。刷新会重置本轮草稿和进度。

## 约两分钟的示范路线

1. 在“给观众做展签”中，将“展件题名”设为“原文”，“制作日期”设为“概括”。此时右侧出现具体题名和年份。
2. 尝试额外把“存放位置”设为“原文”，然后“复核并签发”。系统会指出库位披露过多。改回“移除”后再次签发。
3. 点击“计算并核验”，观察两个相同的 SHA-256 摘要。保存 JSON，用文本编辑器查看实际写入的两个交接字段。
4. 点“模拟改动一字”，再次核验。留底保持原值，接收摘要发生变化。恢复签发副本并重验，便能继续交接。
5. 展开“用签发留底复验本地文件”，选取刚下载的模拟 JSON。也可以另存一个改过的副本，观察两次结果。
6. 返回工作台换成“库位盘点”，同一个库位字段这次需要精确到格。各委托均可直接打开，答题过程互相独立。

## 怎样判断交接合格

每个字段有“移除、概括、原文”三个粒度。委托明确指定完成任务所需的信息。复核会同时指出披露过多与信息不足。概括使用预先编写的独立文本。导出时重新构造 JSON，只写入可交付字段。教学底稿由程序内置，适合公开学习。

程序用浏览器 Web Crypto 对 UTF-8 字节计算 SHA-256。签发时在本轮内存中单独保留基准摘要；改动、恢复或选择本地样本都不会更新这个基准。复验本地文件直接读取字节，换行、空格、BOM 等变化均会影响摘要。单次文件读取上限为 64 KiB。

真实业务需要在受信任的服务端进行鉴权、控制底稿访问并保护留底。本示例只处理虚构字段；浏览器端策略和本地留底用于教学。摘要本身不提供身份认证。本项目无远程调用、持久化、账户或遥测。

## 演示环境

用支持 Web Crypto 的现代桌面浏览器。若部署静态版，使用 HTTPS 或 localhost 以启用摘要功能，保留入口与 assets 的相对路径。窄屏上接收方预览位于字段列表下方。
