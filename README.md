# 开箱必读 · 史实图鉴版

第一届“红码杯”安全代码类示例。七个独立故事取材于 1930–1949 年中央文库的归档、守护、调阅和移交过程。

## 运行

完整解压后，用新版 Edge 或 Chrome 打开 `index.html`。桌面的单文件试玩版可直接打开。目录中的七关均可独立进入或重玩。每关通过后自动弹出史实、短摘和配图，可关闭后再打开。图片随作品离线提供，出处链接需要联网。

1930 年的故事需要展开卷签，判断能否归库，再按日期排列。1931 年的故事需要逐字对读，圈出试抄本中的错字和错序，再按正本誊正。各关有逐步提示，做错可修正。浏览器允许本地存储时，目录记住各关的完成标记。

## 七幕的操作

| 年代 | 场景 | 操作 |
| --- | --- | --- |
| 1930 | 待归文件 | 展开卷签，筛出已办结卷件并按时间归库 |
| 1931 | 双份归档 | 逐字校对，圈记错抄与错序位置 |
| 1932 | 编目柜 | 译读三位暗签，按不同方向查索引并拨动柜门 |
| 1935–36 | 骑缝纸条 | 用边缘记号拼接，排除废抄纸，执行红线印文指令 |
| 1942 | 分包残账 | 对照行总和列总恢复缺失数字，封存独立留底 |
| 1945 | 千里调档 | 按电报自身的封签查译，依次誊抄并打包副本 |
| 1949 | 两联收据 | 读取符号留底，定位总数互相抵消的两处改写 |

完成交接后，可计算两份数字收据的 SHA-256 摘要，再观察改写后的结果。原文节录与虚构的卷记、封令和包数在界面分别标明。游戏内的暗签、替换表和计数方式仅用于情境学习。数字核验展示如何使用可信参照检查字节变化。

## 工程文件

- `index.html`、`assets/game.css` 为入口与界面。
- `assets/scenes.js` 收录档案短摘、出处、场景、数据和摘要函数。
- `assets/puzzles.js` 实现七幕操作及校验。 `assets/game.js` 管理场景切换、提示、章节进度和数字核验。
- `assets/history.js` 和 `assets/history/` 保存通关史实卡、图片及来源。 `创作说明.txt` 记载史料和素材来源。
- `运行截图/` 共五张，来自浏览器实际运行。

静态网站部署时保留相对路径。数字核验使用 Web Crypto，在线部署请用 HTTPS。
